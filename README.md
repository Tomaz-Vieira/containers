# Create a podman dev container for untrusted code

## What

The main script creates a container that is nicely setup to be used as a development container.

Development was done using `podman` but it might transfer trivially to `docker`. The reason is that
`podman` doesn't have a daemon running as `root` on the host, which is probably safer than `docker`.

## Usage

```bash
  python main.py --container-name=mydevcontainer --container-username=builder --ssh-port-on-host=2222
```

This should create a container that can then be started with `podman container start mydevcontainer`.

You can then access the container via something like:

```bash
  podman exec -it -u builder mydevcontainer /usr/bin/bash
```

## Graphical applications

The container should also work with graphical applications, but it needs access to your wayland socket,
which is already mounted into the container, but is only accessible by the virtual "root" user inside
the container. So this means one either has to use the container as "root", or allow other users to
access the wayland socket on the host like so every time you boot the host system:

`your_user@your_host_machine$ chmod 777 /run/user/1000/wayland-0`

I hope to find a more elegant way to fix this in the future

## Getting code in and out of the container

The whole point of using this container is security; if you don't trust some of the code you are running,
either because they come form a non trustworthy source or because they have been generated by AI and
not thoroughly reviewed.

The recommended flow is:

- Log in to the container, `git clone` the repos you are working on in the container
  - Do NOT put your credentails (SSH or otherwise) inside the container.
- Also `git clone` those same repos in your host machine
- Add the repos in the container as a `remote` to the git repos on your host machine:

```bash
  cd my_repo
  # note that 2222 is the value from --ssh-port-on-host
  git remote add container ssh://builder@127.0.0.1:2222/home/builder/source/my_repo
  # now you can fetch from the container's repos:
  git fetch container
  # then you can thoroughly review the code...
  git diff master container/master
  # and merge if you are happy with it
  git merge container/master
```

## Troubleshooting

You can always remove the images and containers created by this script via `podman image rm` and `podman container rm`

## Security tips

- Only push code to github or to the HPC via your host system, who stores the credentials;
- If you are running untrusted code, do not put any credentials inside the container;
- Do not mount your source folder into the container. They can be modified by malicious code that could trigger
  even when running `git` commands on it;
- The container only uses `wayland` for graphical applications because the legacy `x11`
  allows any app to peek into or control any other app;
